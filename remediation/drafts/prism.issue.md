## Problem

It carries no tier tag. The uor-repo-tier app proposes Tier 1 (core framework and critical specs) from its use case, framework: description: "Universal coordinate system for information". Maintainers who record another tier tag change every requirement below; the change set is re-projected from it.

## Proposed Solution

### In a pull request

- Add .github/CODEOWNERS naming @afflom (GOVERNANCE.md 6.1)

### Repository settings an Organization Owner applies

- Require a pull request before merging to the default branch
- Require at least 2 approving reviews
- Require status checks to pass before merging
- Block force pushes to the default branch
- Add topic uor
- Add topic uor-foundation
- Add topic tier-1-core
- Add topic active: it is in normal development, its last commit 2026-05-24 (GOVERNANCE.md 11)
- Add topic math: description: "Universal coordinate system for information"
- Add topic computation: description: "Universal coordinate system for information"
- Add topic rust: GitHub's primary language is Rust, which Linguist names rust

Topics: `active computation math rust tier-1-core uor uor-foundation`. The ruleset is `governance-6.2-t1` in `remediation/apply-settings.sh` of UOR-Foundation/community.

- **check-contexts**: Which status checks must pass? The owner's settings script requires the jobs a pull request reports from workflows that run on every pull request.
- **codeowners**: Should CODEOWNERS name the repository's maintainers instead of the Organization Owner?
- **domain**: Are the proposed Domain topics all that apply?
