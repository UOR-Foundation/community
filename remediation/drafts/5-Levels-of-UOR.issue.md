## Problem

UOR-Foundation/5-Levels-of-UOR does not yet meet the repository standards of UOR-Foundation/.github (STANDARDS.md and GOVERNANCE.md 6.1, 6.2 and 11), observed at `86dde40a976d` of `main`. It carries no tier tag. The uor-repo-tier app proposes Tier 3 (docs, websites and presentation) from its use case, presentation: description: "Explains how the Prime Framework works in 5 levels of difficulty". Maintainers who record another tier tag change every requirement below; the change set is re-projected from it.

## Proposed Solution

### Repository settings an Organization Owner applies

- Require a pull request before merging to the default branch
- Require at least 1 approving review
- Require status checks to pass before merging
- Block force pushes to the default branch
- Add topic uor
- Add topic uor-foundation
- Add topic tier-3-presentation
- Add topic archived: the repository is archived on GitHub, read-only as GOVERNANCE.md 11 defines Archived
- Rename the repository to 5-levels-of-uor
- Add topic documentation: description: "Explains how the Prime Framework works in 5 levels of difficulty"
- Add topic math: description: "Explains how the Prime Framework works in 5 levels of difficulty"

Topics: `archived documentation math tier-3-presentation uor uor-foundation`. The ruleset is `governance-6.2-t3` in `remediation/apply-settings.sh` of UOR-Foundation/community.

- **check-contexts**: Which status checks must pass? The owner's settings script requires the check runs reported on the default branch.

- **copyright-holder**: Is the copyright holder the drafted LICENSE names right?
